# 公开回执与调用预算修复（2026-09-10）

## 已实施的边界

新统一交互桥接层逐路使用 `public_receipt.py` 的递归字段白名单，不再整体透传原生 `info`。原生回执不改动，完整记录留在本地；只有投影后的反馈进入模型消息。

- 保留实际电量、交付能量、功率、已发生的故障结果、设备命令执行标识、规则安装标识及车辆离开时的实际结果。
- 不透传 EV 的原生 reward、厂商 native_info（含总奖励、用户满意度等诊断聚合）、故障 schedule_id、D0 内部状态摘要和重复原生动作。模型已经有自己提交的动作，无需再暴露厂商动作内部结构。
- 未列入白名单的新字段不会自动进入模型消息。预期为标量的位置若出现嵌套数据，停止组装而非透传；消息历史在校验完成前不会追加。
- 空 info 的路由依然使用完整初始公开观测和无损后续增量，未删除观测来缩短上下文。

这是回执边界，不是所有信息泄漏已排除的证明。初始观测及 action schema 还需逐路语义审核；例如公开车辆出发时间是否属于用户已知约定，应由信息契约明确。当前测试中的私有字段扰动检查只证明投影隔离，不能替代原生未来事件的同前缀非干扰验证。旧 pilot runner 未全部迁移，不能自动继承此保证。

## 长会话的明确停止机制

`InferenceBudget` 在发请求前检查序列化消息字节数和累计调用次数，超限抛出明确异常，不发送请求、不推进模拟器、不删历史。已尝试但传输失败的请求也占用调用预算；有隐式重试的 client 被拒绝。

原生两步协议测试使用每路最多 2 次调用、每次消息最多 300,000 字节。长历史诊断使用总计最多 15 次及相同消息字节上限，默认读取修复后的公开回执历史。300 KB 是可复现的本地测试预算，不是模型官方 token 上限或上下文能力声明。provider 仍可能在此范围内拒绝请求；这属于传输/基础设施状态，不是责任失败。

这解决的是安全、透明地停止，不是让任意长历史都能运行。尚未引入历史摘要、滚动窗口或替代观测协议；这些会改变模型可见信息，需单独设计与验证。

## 验证与证据

新增测试检查私有字段剔除、出发回执保留、原始记录不变、所有路由的投影隔离、标量嵌套拒绝、超预算零调用、传输失败计数及隐式重试拒绝。与交互和电池回归联合测试。

`generated/public_receipt_audit_v2/` 为新版本消息回放。电池明确使用 `generated/battery_soc_repair_v1/` 中的修复后完整原生轨迹；其余使用先前完整原生轨迹，并重新读取真实初始观测和接口。它验证格式与重建，不冒充新的 LLM 控制成功率。
