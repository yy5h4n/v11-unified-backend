# Query V2：有限适配与新增后端决策

## 当前建议

本轮不新增后端。下一项最值得做的是 **EV 价格目标的 evaluator/public-information feasibility
spike**，不是立即实现：11 条正式记录中有 2 条独立来源因“按低价时段完成、同时保证离站 SOC”被
拒收，而现有 D1 EV 已有车辆连接、SOC、功率上限、离站时间、需求 SOC 和逐时价格。重复需求证据和
原生状态已经存在，真正缺的是公平地公开未来可用价格信息并定义非唯一策略的成本判分。

这会改变公开任务信息和核心评价目标，需用户确认后再开发。确认前不把当前价格序列当作已知未来，
也不使用 evaluator 的隐私价格轨迹要求 agent 做不可知的最优决策。

## 缺口账目

统计范围是 V2 的 11 条正式记录，加上冻结的人类直接核心搜索中报告的近似来源；它不是需求总体频次。
“可解锁”只是候选上限，同一来源仍须重新走全部门。

| EV 低价且按时充足 | 2（Reddit 直接请求、MIT 产品） | evaluation + public information | 公布预先可得的 tariff horizon；以满足 SOC/功率为硬门，成本 regret 或离散低价机会为次门 | 2 | 最高收益；先做 evaluator spike，需方向确认 |

## EV spike 的验收门

只有以下条件同时满足才建议进入实现：

1. 价格/预测信息确实在决策前公开，且与 evaluator 使用的序列完全一致；
2. SOC、离站、家庭功率和设备故障仍是硬约束，客观不可满足 episode 单列；
3. 成本判分允许多种策略，不要求复现唯一充电时间表；
4. 至少有 idle 失败、只追低价而误离站失败、只追 SOC 但高成本失败，以及一个可行策略通过；
5. 先在原生轨迹上验证，再决定是否付费跑模型；
6. 两条现有拒收记录不能原地改成接受，应生成新版本并保留旧分母。

预计范围：一个公开 tariff 字段/任务条件、一个约束成本 evaluator、原生对照工具和反例测试；不改 EV
物理动力学。如果必须改车辆到离站时间、价格生成过程或故障过程，立即升级为后端范围决策，不在 spike
内继续扩张。

## 何时才值得新增后端

建议门槛是：同一精确缺口至少由两个独立来源组反复触发；现有 route 与有限 task-layer adaptation
无法保留实体、信息条件和结果语义；新增实现能解锁至少两个完整候选；并能预先列出观测、动作、原生
动力学、不可满足处理和 evaluator。当前只有 EV 达到“两个来源”门槛，但初步判断仍可先通过公开信息+
evaluator 解决，尚未证明需要新后端。
