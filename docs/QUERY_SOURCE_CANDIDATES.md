# 需求来源候选核对

这些是来源调查结论，不是已准入的数据，也不是新验证集。

## LLM4QDARE

官方仓库<https://github.com/SyedTauhidUllahShah/LLM4QDARE>列出466条Smart Home需求及两位人工分析员的共识分类标签。原论文第3节明确：两类测试案例来源于PURE，并补充互联网SRS/FRS需求规格文档。论文：<https://ceur-ws.org/Vol-3959/NLP4RE-paper2.pdf>。

因此不能将“人工标注了类别”等同于“来自真实终端用户的原始需求”。下一步如果采用，必须回溯每条规格文档出处及其需求收集证据；当前不作为已验证人类来源。无需下载整库或运行其依赖。其现有类别标签也不能替代本项目责任或后端合同验证。

## Expressing the Needs in Smart Home

论文DOI：<https://doi.org/10.1145/3715114>。出版方搜索索引显示有在线问卷和访谈，并包含开放需求表达；比纯规格文档更接近本项目所需来源。但DOI正文直接读取返回403，尚未定位公开原始数据附件、许可及参与者可隔离标识。不能把论文报告的567问卷样本数说成567条可下载长期query。

当前仅保留为待查候选，没有导入正文数据，也没有冻结验证集。检索SH-RDL、Smart3E和DOI加github未找到可靠原始数据仓库；这不证明其不存在，不替代后续附件检查。

## 下一步边界

继续查出版方补充材料和研究者发布的语料。任何新候选先核实真实人类来源和许可，再做完整库存冻结；不要按能否让现有后端通过来挑验证样本。已有HIIS全部是开发集，不能重新分出未见样本。Mendeley筛查另见MENDELEY_SOURCE_SCREENING.md。
