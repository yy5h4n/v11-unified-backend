# Benchmark 核心与可信底座

## 研究定位

本项目构建 benchmark：评测 LLM 能否通过持续交互，在动态环境中履行用户的长期责任。

用户需求在一段时间内持续有效；环境按自己的动力学和外生过程变化；模型观察变化、发出动作并检查实际结果。评测最终关注责任在整条轨迹上的履行。一次动作被接受、一次设备执行成功、终点状态正常，都不能直接代替轨迹履约。

长期责任表示用于定义任务，不预设为论文的方法贡献。后端与交互协议用于提供可信评测条件，不预设某个控制器、规划器或责任编译器是被测系统的一部分。

## D0–D3 的含义

这些是机制维度，不是必然递增的难度等级，也不是每个episode必须同时具备的四个条件。

| 维度 | 后端必须实际发生的事 | 不足以证明该机制的情况 |
|---|---|---|
| D0 外生变化 | 时间推进带来非模型直接控制的事件或上下文变化 | 只展示时间字段，环境其余状态不变 |
| D1 设备失效 | 故障改变动作可用性或实际执行效果；故障与恢复在环境中有明确语义 | 给观测加一个故障标签，但执行行为未改变 |
| D2 连续演化 | 物理状态随时间累积、消散或滞后，动作改变后续轨迹 | 直接将温度/电量改写成目标值 |
| D3 资源竞争 | 一项服务的动作影响另一项服务可用资源或可交付结果 | 两个独立动作通道并排存在 |

机制归属由证据决定，不能仅按route名称决定。原生模拟器并不天然保证模型设置有效。自建离散状态机也可以可信，只要事件、动作、状态和时间语义明确且可验证。

所有15条正式route必须保留在覆盖清单；BOPTEST作为尚未形成正式route的候选单列。覆盖清单齐全不等于全部能力已验证。FDS重放与原生在线推进分别记录；CityLearn单楼多系统在共享约束未验证前不计作强D3证据。

## 本阶段范围

先完成后端与交互基础设施验收。暂缓query construction、正式数据入集、模型能力结论和规模化。手写请求和控制脚本仅用于诊断底座。参考控制器可以证明某个环境轨迹可执行，但不能自动证明benchmark任务有效。

## 后端可信性的验收要求

1. **时间与因果**：明确模拟时间、一步跨度及内部子步；未来动作不得影响已观察到的过去。观测和接口查询不推进时间。
2. **状态与动作**：观测来自实际后端状态；动作范围、单位、持续性、应用时刻和执行延迟明确。不隐式裁剪、补齐或替模型选择动作。
3. **外生机制**：环境事件与模型动作分离；当前已发生的故障/事件按公开观测能力暴露，未来隐藏事件不可泄漏。
4. **原生过程**：连续变化由选定模拟器计算；声明模型边界、单位和尺度。原生输入场景变化与Python代理更新必须区分。
5. **共享资源**：用固定另一侧动作的双向干预验证相互影响；真实物理限制与benchmark额外约束分别标明。
6. **运行状态**：终止、时间截断、动作拒绝、设备执行失败、模拟器异常有不同回执含义。reset后不能残留上个episode的状态。

每项验收包含可执行检查和结果。仅有接口连通或idle/witness对照不能替代以上检查。

## 基础交互协议

本阶段采用逻辑模拟时间：LLM推理期间模拟时钟暂停。模型通过动作和自主等待指定下一次决策时间；后端按该route的原生间隔逐步推进，直到等待截止、指定公开事件成立或终态。推理耗时单独记录。将真实推理延迟计入环境时间属于另一个实验条件，不能混入同一结果。

原生推进间隔不等于模型调用频率，不将所有后端压成8次调用。等待期间每个原生间隔的公开状态与回执保留，在唤醒时无损返回；模拟器内部更细子步并不因此成为公开观测。若事件驱动提前返回，必须明确报告实际推进时间。连续控制显式保持设定，离散命令只执行一次；不存在偷偷替模型处理故障的控制器。

模型初始获得：

- 当前任务和必要的公开服务条件（接入query阶段再细化）。
- 完整初始观测、当前模拟时间、单位和观测字段解释。
- 完整动作外层格式、字段、范围、合法示例、保持/等待语义。
- 动作与时间推进规则、反馈格式、错误处理及调用预算。

随后使用现有主协议：**完整初始状态 + 按顺序无损增量 + 动作结果**。不能省略初始值或截掉重建所需历史。完整状态模式仅作独立诊断条件。公开预报/日程可以提供，但必须作为明确的环境信息条件，不能偷偷暴露隐藏故障表。

区分三件事：指令是否被接受、设备实际执行了什么、环境结果变成什么。不能因为指令被接受就报告任务成功。持续保持上次设定、等待、不操作的含义按route声明；“关设备”不能自动当成通用no-op。

解析器只解析和验证，不承担控制决策：不从长篇文本里猜动作、不补默认动作、不修正功率、不自动重试设备控制。JSON外层包装兼容范围需固定。

格式错误或纯接口校验失败可以在尚未推进后端前返回结构化错误。纠错次数是显式实验设置，所有尝试均记录；先前pilot的两次纠错不是已经确认的正式benchmark设置。正常设备故障应继续推进其对应时间并返回实际结果。原生异常若无法保证状态一致，终止该运行并标为基础设施错误，不替模型重置后接着跑。

## 当前必须补齐的工程缺口

| 项目 | 当前证据 | 需要完成 |
|---|---|---|
| 增量观测 | 15路由完整原生记录通过统一消息格式与无损重建 | 真实模型测试、长会话预算；旧runner尚未全部迁移 |
| 动作格式 | 15路由桥接层含原生schema、示例及动作语义 | 真实模型逐路验证理解与解析，不能用脚本回放代替 |
| 非法动作 | 15路由接入纯预检，SustainGym另检查原生零HVAC区域掩码 | 扩充边界输入覆盖，保留未知异常中止保护 |
| 故障回执 | 工作流规则安装/触发已分离；四条D1有真实故障结果对照 | 不等于全部故障或恢复策略覆盖 |
| 无动作/保持 | 逐路公开；D0已支持真正无命令wait；连续路线保持已有显式控制，不能凭空补0 | 不擅自替agent选择空动作；自主等待证据见AUTONOMOUS_WAIT_COVERAGE_STATUS.md |
| 原生执行隔离 | 有些route依赖独立Python环境，顺序导入可掩盖缺依赖 | 每条route独立启动检查，不能依赖先运行别的后端 |
| 全后端验收 | 当前15路由基本交互及seed 0完整时域验收通过；机制另有分类对照 | 任务可行性、长期责任与评估仍需单独验收 |
