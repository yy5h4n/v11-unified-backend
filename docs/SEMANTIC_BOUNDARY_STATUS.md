# 语义边界验收进展（2026-09-10）

## 本轮真实修复

CityLearn 单楼双系统原本在原生推进后直接发送下一输入行：SOC/能耗可能尚未写入，室温也不对应刚完成的受控状态。现在动作后将 SOC、室温和电耗读取位置对齐到实际完成的原生步；天气、外生负荷、时钟等仍是下一决策的输入。多楼路由同步将每楼 SOC、室温、电耗与共享电表所使用的完成步对齐。模型提示明确区分这两种时间口径，不允许把下时段负荷与上时段耗电拼成能量平衡。

新增测试逐个比较公开字段与原生 building 数组，包含充电、放电、零请求及 district 电表求和。两个路由各 24 步完整运行通过，原始证据位于 `generated/citylearn_completed_state_v1/`。单楼/多楼相关回归与交互格式共 39 项通过。

workflow 白名单另修复了 `feedback.applied` 的真实类型：它是已执行命令 ID 列表，而不是完整命令记录列表。补了原生非空车库开门动作到增量会话的测试；此前仅空动作回放无法覆盖这个缺口。

旧 CityLearn 轨迹和模型测试保留为历史证据，不能冒充本轮修复后的验证；原先完整会话回放需要读取新原生轨迹后再生成。未重新发起付费模型调用。

## 可重复执行的检查

`python tools/audit_semantic_boundary.py` 输出 `generated/semantic_boundary_v1.json`，保留全部 15 路由，缺少独立检查的一律标记 pending，不用空检查凑通过。

- 7 路由有通过的限定语义检查：D1 电池/EV、D3 单楼/多楼/EV/供热、D2 WNTR。范围包括观测与回执一致、分量求和、共享余量等，不能当作全部变量物理正确性的证明。
- D0 和四条 D1 的既有原生健康/故障或外生对照中，初始状态加第一步的完整公开消息一致。这只说明该有限前缀不被对应未来安排区分，不是所有未来安排、全部时段或 schema 的无泄漏认证。
- 其余语义检查、初始观测的逐字段信息契约、warm-up 边界语义与真正完整时域的 LLM 运行仍待验收。当前所有路由 `foundation_ready` 保持 false。

模拟器和回执“字段相同”并不一定代表语义相同；本工具只比较明确对齐的量。尤其区间能耗与下一区间外生输入、车辆离开后的空端口与离开前 SOC，不能直接机械相等比较。
