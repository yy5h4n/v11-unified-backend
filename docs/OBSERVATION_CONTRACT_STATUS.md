# 观测契约与长运行验收（2026-09-10）

`unified_compiler/observation_contracts.py` 给出全部15条路由的公开字段、单位、时间口径和公开信息条件；统一提示现已包含它。运行器在发送初始状态前、发送每个新观测前检查顶层字段、部分嵌套结构、有限JSON以及明确的私有诊断字段。不悄悄删除未知观测字段来凑通过；遇到未审查字段停止并按基建问题报告。

该检查不是“任意字段都已证明安全”：workflow 包含动态公开设备状态、消息和接口结构，当前还不是完整逐叶类型白名单。不能只靠禁止词检查宣称无泄漏。已补充 D3 EV 的空端口约束：未连接车辆不能出现 SOC、离开时间或目标能量，防止尚未到达的车辆计划提前曝光。已连接车辆的离开时间属于明确公开的信息条件。

进一步澄清：

- SOC 为0–1，湿度为百分比；WNTR压力为水头米，流量为m³/s；热流为W而非累计能量。
- SustainGym occupancy_power_kw 为原生有符号显热模型输出，不是人数/占用传感器；不能把负值默改为0。
- CityLearn 的原生 building.apply_actions 明确以负值冷却、正值供热，现已写入两条D3提示；大小是归一化设备输入，不是温度设定值。
- Workflow 的公开 SLA、截止时间、allowlist 与库存投影是已声明服务条件/预测，不是隐藏事件表；事件/故障未来表仍不公开。

## 本轮新增修复

SustainGym 传感器漂移的观测原本按当前步增长，但 sensor_health.correction 一直显示故障起始偏移。现在按当前步给出一致的诊断值。该值属于本接口显式暴露的传感器诊断，不声称这是盲故障识别任务。六种原生故障预设重新对照验证通过；默认路由从新鲜原生 failed-profile 证据重新生成入口验证记录。

同时修复 probe_d1_fault_profiles.py 的 --check：以前会重写结果，现在只比较并拒绝缺失/过期记录，连缺失目录也不会创建。独立测试验证它不会把旧失败文件覆盖成成功。

## 同一个运行器的完整原生执行

`tools/check_native_session_path.py` 在生产 session 路径上使用明确标注的脚本客户端，实际运行全部原生后端，而非仅重放消息。15/15完整时域通过，共953步，回执、字段校验、消息重建、终态和关闭均完成。证据：`generated/native_session_path_v1/`。

这是脚本客户端，不是真实LLM；外部API调用为0，不作为模型能力结果。真实闭环仍因API连接被重置而未完成。本轮复查同一已授权域名仍连接失败，没有更换域名或关闭TLS校验。

不截断历史时，SustainGym288步累计消息约169.83MB、EnergyPlus287步约31.74MB、D3 EV96步约4.34MB。这是反复提交会话的累计序列化字节，不是单次上下文长度、token数或账单。说明完整长历史路径确实可运行，但真实模型成本/上下文能力尚未得到验证。FDS完整重放约499秒，不能算作模型推理延迟。

相关回归65项通过；原生故障预设六项均通过。底座目标仍active：真实模型完整运行、长历史可用策略、统一最终发布验收仍未完成，不能开始数据构造。
