## 单独的接口诊断（不计入自然责任能力结果）

明确要求模型开灯后等到公开occupancy_status变成away，再关灯等到终态。

第一次 `autonomous_wait_llm_event_diagnostic_v1/`：模型构造了不存在的前缀public，等待条件始终不匹配，1次调用直接等到终态。公开上下文确实在120秒变为away，但未唤醒。运行器按所给路径运行；任务层面的事件等待意图失败。提示原先的示意路径 `["public","field"]` 易误导，不能简单只归为模型错误。这条失败证据保留。

修复只澄清路径从当前重建观测根开始，不允许擅自添加public/observation等消息前缀，不改调度行为、不自动纠正模型路径。新增提示回归测试；相关25项通过。

第二次 `autonomous_wait_llm_event_diagnostic_v2/`：相同诊断query，模型给出正确的context路径。120秒因公开事件唤醒，第二次决策执行关灯并等到720秒终态。**2次真实模型调用、12个原生步（2+10）**；全部中间状态和回执保留，独立批次审计通过。输入4041、输出102、合计4143 tokens。

它证明真实模型API可以执行长等待和事件唤醒，不证明模型面对自然责任会自主做出好的时间决策。不能把诊断中的显式策略当作自然任务成功率。

本轮总计46次API调用：自然任务43次、失败诊断1次、修复后诊断2次；合计输入266839、输出1860、总tokens268699。所有消耗均按provider usage，不换算货币账单。

结论：接口已有真实跨步/事件唤醒证据；自然任务尚无决策次数降低证据。后续应分开对照提示示例影响与任务对决策频率的要求，并评估等待期间轨迹结果，而不是直接扩大高消耗运行。没有开始数据构造，也没有宣布底座最终交付完成。

`tools/probe_wait_example_bias.py` 与 `generated/wait_example_bias_v1.jsonl`：同一D0初始公开状态和query、同一当前路径说明，仅将格式示例等待改为60/180/360秒，各一次请求。三次模型都选择60秒。这个有限对照不支持“仅仅照抄格式示例时长”的解释，但只有一个状态、每条件一个样本，不能证明不存在提示偏置或模型策略最优；没有据此修改任务或强迫模型长睡眠。该对照不执行模拟器、不产生任务成功率。
